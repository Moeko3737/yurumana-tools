# ゆるまなTools 🌱

「学びを、ちょっとラクに。」ZEN大学生の履修・学習計画を支援する、学生個人制作の非公式ツール集です。

## ゆるまな履修ナビ

曜日ごとの学習可能時間から、開始日〜最終締切（両端を含む）の総時間とオンデマンド科目の履修量を計算します。全15回、1レポートあたり150／120／100分（視聴・確認・復習・課題を含む）の3モデルで科目数を切り捨て、2単位科目の場合の単位相当を添えます。入力は即時反映されます。祝日は通常／0分／別時間の3通りで補正します。

## ファイル構成


新しいツールは別フォルダーを作り、common.cssを相対パスで読み込み、TOPにリンクを追加できます。サーバー処理・ビルド・外部ライブラリ・APIキーは不要です。

## 祝日データの更新

出典：[内閣府「国民の祝日」](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)、[公式CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)。2026年10月5日に取得した1955〜2027年のデータを同梱しています。振替休日・国民の休日も含みます。サイト実行中のネットワーク取得はありません。

`assets/data/holidays.js` の `JAPAN_HOLIDAYS` に、年をキーとして `"YYYY-MM-DD": "祝日名"` を追加してください。例：

```js
"2027": {
  "2027-01-01": "元日",
  // 当該年の祝日・休日をすべて記載する
}
```

年のデータは必ず1年分すべてを登録してください。公式CSVは通常CP932（Shift_JIS系）です。締切の年を変える際は、その年と対象期間に含まれる年のデータを確認してください。データがない年は計算を止めて案内します。1955年は法律施行後の収録範囲です。

## GitHub Pagesで公開する方法

1. GitHubで `yurumana-tools` リポジトリを作成します。
2. このフォルダーの**中身**をリポジトリのルートに配置します（index.htmlが最上位）。`yurumana-tools` フォルダー自体をさらに入れ子にしないでください。
3. GitHubの **Settings → Pages → Build and deployment** で **Deploy from a branch** を選びます。
4. **main** ブランチと **/(root)** を選択し **Save** します。
5. 公開完了後、`https://ユーザー名.github.io/yurumana-tools/` と `https://ユーザー名.github.io/yurumana-tools/rishu-navi/` を確認します。

全て相対パスで、別のリポジトリ名のサブディレクトリでも動作します。アカウントへのアップロード・Pages設定はこの成果物とは別に行ってください。

## 前提条件

- JavaScript有効の現行ブラウザを想定。端末のローカル日付を「今日」として使います。
- 日付の走査と曜日判定はUTCで統一し、夏時間・時差で1日ずれないようにしています。
- 入力は保存しません。再読み込み時は今日・全曜日0分・祝日普段どおりに戻ります。
- 学習可能日数は祝日補正後の時間が0分を超える日数です。
- 平均週あたり＝総時間÷カレンダー日数×7。表示時のみ1分単位に四捨五入します。科目計算は総分数を直接使い、切り捨てます。
- 履修量は参考値です。ライブの0.5科目換算も厳密な換算ではありません。正式な条件・日程・締切は大学の公式情報を確認してください。

4Qの期間切り替えを追加。2026-12-14〜2027-02-14は両端を含め63日、毎日120分で126時間、祝日を休みにすると120時間です。冬季休業は自動的な休みにはせず、曜日設定・祝日設定に従います。

## ゆるまなペースナビ 🌱

`pace-navi/` は、履修済み科目の進捗と使える時間から、締切までの必要回数・必要時間・日ごとのおすすめ本数を確認するツールです。履修ナビが「何科目取れそう？」、ペースナビが「どのくらい進めよう？」、履修スケジュール管理表が「いつ何をやろう？」を担当します。

### 主な機能とファイル

- 6区分で科目登録。科目名・色・想定時間・演習曜日を設定できます。
- 完了数の一括入力と各回の個別完了（飛び飛び可）。既存の記録を一括変更する際は確認を表示します。
- 動画・確認レポートの任意詳細記録。提出済みをチェックすると、その回の動画と完了状態も連動します。
- 「次の締切まで」「最終締切まで」の切り替え、日別本数、時間不足の表示。最初は7日、残りは開閉できます。
- 演習は曜日＋休講日の補足表示。完了科目は残し、完了表示にします。
- localStorageによる自動保存、JSONバックアップと復元。科目削除・全リセット・復元には確認を表示します。

```text
assets/data/academic-config.js   年度・科目区分・締切・回数・Q開始日
pace-navi/index.html             ペースナビの画面・説明
pace-navi/style.css              共通CSSを補う専用スタイル
pace-navi/script.js              科目管理・入力・描画・バックアップ操作
pace-navi/engine.js              進捗・締切判定・日別配分
pace-navi/storage.js             保存・バックアップ形式検証
tests/pace.test.cjs              ペース計算とデータ検証テスト
```

`assets/css/common.css` のデザインと、既存の `rishu-navi/calculator.js` の時間表記・日付処理・祝日判定を再利用しています。履修ナビのコード・設定は変更していません。ビルド工程やサーバー処理は不要です。

### 科目タイプごとの扱い

| 区分 | 全回数 | 詳細 | 累積締切目標 |
| --- | --- | --- | --- |
| オンデマンド3Q | 15 | 動画6本＋確認レポート | 10/29に5回、11/12に10回、11/29に15回 |
| オンデマンド4Q | 15 | 動画6本＋確認レポート | 2027/1/13に5回、1/28に10回、2/14に15回 |
| pixiv3Q | 8 | 動画1本＋確認レポート | 10/29に1回、11/29に8回 |
| pixiv4Q | 8 | 動画1本＋確認レポート | 2027/1/13に1回、2/14に8回 |
| ライブ | 15（3Q〜4Q通年） | 動画1本＋確認レポート | 11/29に5回が目安、2027/2/14に15回 |
| 演習 | 15 | 各回の完了だけ | ペース計算に含めない |

「1本」は、オンデマンド・pixiv・ライブ科目の授業1回分です。動画1本ではなく、視聴・確認・復習・課題を含むまとまりの目安です。演習の授業時間は自主学習時間から差し引きません。

途中締切はソフト締切として、経過後も未完了分を次の累積目標へ含めます（成績に影響する場合があります）。最終締切はハード締切として、経過後は警告を表示して未来の配分から除きます。完了済み・期限超過の科目も自動削除しません。

### 締切・開始日の変更

`assets/data/academic-config.js` に `academicYear`、`q3Start`、`q4Start`、各 `sections` の `totalSessions`・`videos`・`milestones` をまとめています。今回の日程はユーザー提供の締切表、開始日はこのチャットで確認済みの学事暦（3Q 2026-10-06、4Q 2026-12-14）によります。

`q4Start` が未設定（`null`）の場合は、3Q最終締切の翌日を最低限の配分開始日として使い、3Q最終締切以前へ4Qの作業を混ぜません。この代替日は正式な授業開始日ではありません。年度更新時は正式な日程を確認して設定してください。

祝日は既存の `assets/data/holidays.js` を使います。更新方法・内閣府の出典は上記「祝日データの更新」を参照してください。

### 計算・日別配分

1. 各回の完了状態の個数を数えます。まとめて設定した場合は1〜N回が完了です。動画だけの部分完了は必要時間から減らしません。
2. 次の締切モードは、未達成かつ開始日以降の締切を科目ごとに探し、その中で最も早い日を対象にします。既に目標回数を達成した途中締切は飛ばします。同日の科目だけを合算します。
3. 最終締切モードは、各科目の最終締切をそれぞれ保持します。早い締切から時間を確保し、3Qの作業を2月へ先送りしません。同じ締切なら開始可能日の遅い作業から確保します。
4. 同じ締切・開始可能日の作業ごとに「残り回数×各科目の想定時間」を合計し、残り回数で割った加重平均を1本の配分時間として使います。画面全体にも加重平均を表示します。
5. 各日の可能時間（祝日補正後）に比例配分し、端数は最大剰余方式で配ります。同じ端数なら可能時間が多い日、さらに同じなら早い日を優先します。1日に収まる整数本数が上限です。先に配分した作業の時間は後のグループから差し引きます。
6. 配置できない本数は残し、未配置本数×配分平均時間を未配置作業時間として表示します。総時間不足とは別です。0分の日へは配置しません。科目名を日付へ自動配置しません。

### 保存とJSONバックアップ

localStorageのキーは `yurumana-pace-navi-v1`。科目・色・タイプ・進捗・詳細記録・想定時間・演習曜日/休講日・学習時間・祝日・開始日・モードを保存します。同じURLの同じブラウザで復元されます。端末間の自動同期やサーバーへの送信はありません。履修ナビのデータには影響しません。

バックアップは `schemaVersion: 1` のJSONファイル。読み込み時は日付、数値、区分、回数、重複ID、動画/提出の整合性などを検証し、確認後に全データを置き換えます。不正なデータは拒否し、元データを維持します。読み込めないlocalStorageを検出した場合は、自動保存を止めて元データを保護します。正常なバックアップの復元またはリセットで保存を再開できます。保存できないブラウザでは案内を表示し、バックアップ書き出しを利用できます。

### 既知の制約

- 想定時間と加重平均による目安です。科目を特定して割り振る計画や成績予測ではありません。実際の科目負荷の差によって、個別の1日分の作業が提案と異なる場合があります。
- 1本を複数日に分割しません。毎日短い時間でも、合計時間は足りる一方で配置できない場合があります。
- 最終締切モードは最終締切を守るための計算です。途中締切の達成も確認したい場合は「次の締切まで」を併用してください。
- 冬季休業は自動除外しません。演習は曜日＋休講例外のみで、全15回の実施日・補講・課題締切は計算しません。演習しかないときは開始日から7日間の曜日メモを表示します。
- 開始日の不正な一時入力は保存しません。カスタム時間の未入力は保存できますが、ペース計算を止めて正の整数の入力を案内します。
- 入力・バックアップの保護のため、科目数500件、科目名200文字、想定時間1〜1,000,000分、休講日1,000件/科目、読み込みファイル5MB以下を上限にしています。
- ユーザー設定で古い年を選んでも、祝日データがない年は計算を止めます。
- 学生個人制作の非公式ツールです。正式な締切・授業条件は大学公式情報を確認してください。成績や単位取得を保証しません。

### ペースナビの初回登録と設定画面

初回は「科目登録 → 勉強できる時間」の2段階のポップアップで設定します。「あとで設定」で閉じることもできます。普段の本画面には進捗管理とおすすめペースを表示し、科目名・色・想定時間・演習曜日/休講日、学習時間、バックアップは「設定」の科目/学習時間/データから編集します。動画・レポートの詳細進捗や一括完了は本画面で使えます。

既存の登録データはそのまま利用し、登録済みのユーザーには初回案内を出しません。初回案内の完了状態は別のlocalStorageキー `yurumana-pace-setup-v1` に保存します。学習データとJSON形式は変更していません。バックアップを新しい端末で復元した場合も初回案内を完了扱いにします。全データをリセットすると初回登録に戻ります。

設定画面はネイティブdialogを使用し、背景の操作を止め、Escで閉じ、閉じた後は設定ボタンへフォーカスを戻します。320px幅の登録・時間設定、本画面の進捗連動、既存データの保持、再訪問、バックアップ操作を確認しています。
